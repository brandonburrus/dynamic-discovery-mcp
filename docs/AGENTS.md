# docs/ — Documentation Site

The user-facing documentation site for `dynmcp`. Built with [Astro](https://astro.build) + [Starlight](https://starlight.astro.build) and themed with [`starlight-theme-flexoki`](https://github.com/delucis/starlight-theme-flexoki). Published to GitHub Pages on every GitHub Release at the custom domain **dynamicmcp.tools**.

## Purpose

`README.md` is intentionally a short feature overview + getting started. `SPEC.md` is the authoritative project blueprint. This docs site is the **user-facing reference** that draws from both — guides, API reference, and conceptual explainers structured for first-time readers.

If you change behavior described in `SPEC.md` or `README.md`, the corresponding page under `docs/src/content/docs/` should be updated in the same PR.

## Layout

```
docs/
  astro.config.mjs              # Site config: title, sidebar, social links, flexoki plugin
  src/
    content.config.ts           # Astro content collections (Starlight schema)
    content/
      docs/
        index.mdx               # Landing page (splash hero)
        start/                  # Getting started (intro, installation, quick-start)
        guides/                 # Task-oriented walkthroughs
        reference/              # Field-by-field reference
          tools/                # discover_tool, use_tool, load_mcp
        concepts/               # Architecture, proxy behavior, capabilities, lifecycle, namespacing
  public/
    CNAME                       # dynamicmcp.tools custom domain for GitHub Pages
```

## Sidebar

The sidebar is **explicitly configured** in `astro.config.mjs`, not autogenerated. When adding a new page, update the sidebar config in the same change. Each `slug` in the sidebar must match the file path under `src/content/docs/` (without the extension).

## Theming

The site uses `starlight-theme-flexoki` for the [Flexoki](https://stephango.com/flexoki) colour palette. The plugin is wired up in `astro.config.mjs`:

```js
import starlightThemeFlexoki from "starlight-theme-flexoki";

starlight({
  plugins: [starlightThemeFlexoki()],
  // ...
});
```

Do not introduce additional global CSS overrides unless absolutely necessary — let the theme do the work.

## Local development

```bash
cd docs
npm install
npm run dev         # http://localhost:4321
npm run build       # static output in docs/dist/
npm run preview     # serve built output
```

The build runs `astro check` first (type-checking against the content collection schema) and then `astro build`.

## Publishing

Deployment is handled by `.github/workflows/docs.yml`:

- **Trigger:** every GitHub Release publish (`on.release.types: [published]`), plus manual `workflow_dispatch`.
- **Build:** `npm ci && npm run build` inside `docs/`.
- **Deploy:** `actions/configure-pages` + `actions/upload-pages-artifact` + `actions/deploy-pages` (the standard GitHub Pages flow). The CNAME file in `public/` is included in the artifact, so `dynamicmcp.tools` is preserved.

GitHub Pages must be configured to use **GitHub Actions** as the source (not the legacy "branch" source). DNS for `dynamicmcp.tools` must be pointed at GitHub Pages per [GitHub's docs](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site).

## Conventions

- **Sentence-case headings.** Match Starlight's default style.
- **Internal links use trailing slash paths:** `/guides/dynamic-discovery/`, not `.md` filenames. Starlight resolves these by slug.
- **Code examples are runnable.** Prefer the exact form a user would actually type (`npx dynmcp@latest -- ...`) over abbreviations.
- **No emojis** unless the user requests them. The README's no-emoji rule applies here too.
- **Be wary of duplicating SPEC.md verbatim.** Reference pages should describe behavior in user-facing language; SPEC.md is the implementation contract. If they conflict, SPEC.md is authoritative and the docs page should be updated.

## Schema endpoint

The JSON Schema for the dynmcp config file is served by this site at **`/config.json`** (canonical URL: `https://dynamicmcp.tools/config.json`). This is the URL baked into the schema's `$id` and what users put in their config files' `$schema` field for editor validation.

The file at `docs/public/config.json` is **generated** by `scripts/generate-schema.ts` in the parent project, which writes directly into this site's `public/` directory so Astro auto-includes it in the build. This is the single distribution channel for the schema — the npm tarball no longer ships its own copy. Never edit `docs/public/config.json` by hand; re-run `npm run generate:schema` at the repo root after any schema change, or rely on the `prebuild` hook to do it on every build.
